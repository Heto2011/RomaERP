# RomaERP

نظام تخطيط موارد المؤسسات (ERP) — يغطي **المحاسبة المالية**، **الموارد البشرية**، و**المخزون**، مبني بـ Clean Architecture.

## التقنيات

- **Backend:** ASP.NET Core 8 Web API (C#), Clean Architecture (Domain / Application / Infrastructure / API)
- **Database:** SQL Server + Entity Framework Core
- **Auth:** ASP.NET Core Identity + JWT، مع صلاحيات حسب الدور (Admin / Accountant / HR / Employee)
- **Frontend:** React + TypeScript + Vite

## هيكل المشروع

```
src/
  RomaERP.Domain          # الكيانات والـ Enums (لا تعتمد على أي مكتبة خارجية)
  RomaERP.Application     # DTOs + منطق العمل (Services) + الـ Interfaces
  RomaERP.Infrastructure  # EF Core DbContext, Migrations, Identity, JWT
  RomaERP.API             # Controllers, Program.cs, Swagger
tests/
  RomaERP.UnitTests
frontend/                 # React + TypeScript
```

## الموديولات الحالية

### المحاسبة المالية
- شجرة حسابات كاملة (أصول / خصوم / حقوق ملكية / إيرادات / مصروفات) مبنية على أساس الاستحقاق المحاسبي، بما فيها حسابات **المصروفات/الإيرادات المقدمة والمستحقة**.
- سنوات وفترات محاسبية.
- قيود يومية بنظام القيد المزدوج (Double-Entry) مع التحقق من التوازن، والترحيل، وعكس القيود.
- ميزان المراجعة.
- **قائمة الدخل** و**قائمة المركز المالي** (مبنيتين مباشرة من القيود المرحّلة).
- **إقفال الفترات والسنوات المالية**: إقفال فترة يمنع الترحيل عليها، وإقفال السنة ينشئ قيد إقفال تلقائي يصفّر حسابات الإيرادات والمصروفات ويرحّل صافي الربح/الخسارة لحساب الأرباح المرحلة.
- **الأرصدة الافتتاحية**: شاشة مخصصة لإدخال ميزان المراجعة النهائي القادم من نظام العميل القديم عند بدء الاشتراك، بدل البدء من صفر — تتحقق من توازن الأرصدة وتمنع الإدخال المزدوج لنفس السنة المالية.

### الموارد البشرية
- الأقسام والوظائف والموظفون.
- عناصر الأجر (بدلات / استقطاعات) قابلة للربط بحسابات دليل الحسابات.
- دورات رواتب: إنشاء وحساب تلقائي → اعتماد → ترحيل، وينتج عنها قيد محاسبي تلقائي (مصروف مرتبات مقابل مرتبات مستحقة).

### المساعد الذكي للمصروفات (Claude AI)
- شاشة محادثة: الموظف يكتب المصروف بلغة طبيعية (مثال: "اشتريت بنزين بـ100 جنيه")، والمساعد (Claude API) بيستخرج المبلغ والوصف وأنسب حساب مصروفات من دليل الحسابات تلقائيًا.
- لو المبلغ مش واضح، المساعد بيسأل توضيح. بعد ما يتحدد المبلغ والبند، بيسأل على مرحلتين:
  1. **"عهدة ولا جاري (حساب الشركة)؟"** — عشان يعرف مصدر تمويل المصروف الأول.
  2. لو **جاري**: يسأل بعدها **"كاش ولا شبكة؟"**.
     - **كاش:** يروح مباشرة لشاشة "اعتماد المصروفات" في انتظار موافقة المدير.
     - **شبكة:** يفضل معلّق (مع إمكانية إرفاق صورة الإيصال كإثبات) لحد ما يتطابق تلقائيًا مع كشف حساب البنك، وبعدها يروح هو كمان لانتظار الاعتماد.
  3. لو **عهدة**: يسأل عن اسم/كود الموظف صاحب العهدة (بدون سؤال كاش/شبكة، لأنه مش مهم مع العهدة)، وبمجرد ما يتحدد الموظف يروح مباشرة لانتظار الاعتماد.
- **محاسبة العهد:** حساب واحد إجمالي في دليل الحسابات ("عهد الموظفين" — كود `1170`، أصول متداولة) مع رصيد فرعي لكل موظف (زي حسابات العملاء). عند الاعتماد يتسجل قيد **مدين مصروف / دائن عهد الموظفين**، وبينقص رصيد عهدة الموظف بقيمة المصروف تلقائيًا.
- **المطابقة البنكية:** رفع كشف حساب (CSV) أسبوعي/شهري، مطابقة تلقائية بالمبلغ والتاريخ (خلال ±5 أيام)، ومطابقة يدوية للحالات الغامضة.
- **الاعتماد إجباري دايمًا:** لا يوجد أي مصروف من المساعد الذكي (عهدة، كاش، أو شبكة) بيترحّل في الحسابات من غير موافقة صريحة من **Admin فقط** على شاشة "اعتماد المصروفات" — الاعتماد بينشئ القيد المحاسبي، والرفض بيلغي الحركة بدون ترحيل.
- **محتاج مفتاح Claude API** (راجع "تفعيل المساعد الذكي" تحت) — من غيره الشاشة بتشتغل وبترجع رسالة واضحة إنه لازم يتفعّل، من غير ما تعطل باقي النظام.

### المخزون
- أصناف وتصنيفات ومخازن.
- حركات استلام وصرف بنظام **المتوسط المرجح للتكلفة** (Weighted Average Cost)، مع منع صرف كمية أكبر من الرصيد المتاح.
- كل حركة بترحّل تلقائيًا للمحاسبة (استلام: مدين مخزون / دائن موردين — صرف: مدين تكلفة بضاعة مباعة / دائن مخزون)، مع إمكانية الربط بمركز تكلفة.

## الصلاحيات حسب الدور

| الدور | الوصول |
|---|---|
| Admin | كل شيء، بالإضافة لإقفال السنوات المالية وفتح الفترات |
| Accountant | المحاسبة الكاملة (حسابات، قيود، تقارير، إقفال فترات)، المخزون، المساعد الذكي والمطابقة البنكية، ومشاهدة/ترحيل الرواتب |
| HR | الموارد البشرية الكاملة (موظفين، رواتب، اعتماد دورات الرواتب) |
| Employee | وصول عام فقط (بيانات مرجعية مثل الفترات المالية) — لا يشوف بيانات مالية أو رواتب حساسة |

## التشغيل محليًا

### المتطلبات
- .NET 8 SDK
- SQL Server (أو container عبر Docker)
- Node.js 18+

### 1. قاعدة البيانات

```bash
docker run -d --name romaerp-sql -e "ACCEPT_EULA=Y" -e "MSSQL_SA_PASSWORD=YourStrong@Passw0rd" -p 1433:1433 mcr.microsoft.com/mssql/server:2022-latest
```

عدّل `ConnectionStrings:DefaultConnection` في `src/RomaERP.API/appsettings.json` عند الحاجة.

### 2. الـ Backend

```bash
dotnet tool install --global dotnet-ef
dotnet ef database update --project src/RomaERP.Infrastructure --startup-project src/RomaERP.API
dotnet run --project src/RomaERP.API
```

عند أول تشغيل (Development) يتم تلقائيًا زرع (Seed):
- دليل الحسابات الأساسي، السنة المالية الحالية وفتراتها الشهرية، مخزن ومركز تكلفة وقسم افتراضي.
- مستخدمين تجريبيين لكل دور (كلمة المرور لكل الحسابات: `Passw0rd!123`):
  - `admin@romaerp.local` (Admin)
  - `accountant@romaerp.local` (Accountant)
  - `hr@romaerp.local` (HR)
  - `employee@romaerp.local` (Employee)

الـ API متاح على `https://localhost:xxxx/swagger`.

### تفعيل المساعد الذكي (اختياري)

المساعد الذكي محتاج مفتاح API من [console.anthropic.com](https://console.anthropic.com) (منصة مطورين منفصلة عن حساب claude.ai، وليها فوترة pay-as-you-go). بعد ما تجيب المفتاح، **متحطوش في appsettings.json** — استخدم واحدة من الطرق دي:

```bash
# تطوير محلي (دوت نت user-secrets)
cd src/RomaERP.API
dotnet user-secrets set "Claude:ApiKey" "sk-ant-..."

# أو environment variable (بيشتغل في أي بيئة، فيه Docker/سيرفر إنتاج)
export Claude__ApiKey="sk-ant-..."
```

من غير مفتاح، شاشة "المساعد الذكي" بتشتغل عادي بس بترجع رسالة واضحة للمستخدم إنه لازم يتفعّل، وباقي النظام مش بيتأثر.

### 3. الـ Frontend

```bash
cd frontend
npm install
npm run dev
```

عدّل `VITE_API_URL` في `frontend/.env` إذا لزم.

## الخطوات القادمة
- تكامل المخزون مع المبيعات/المشتريات الفعلية (فواتير) بدل حركات يدوية.
- صلاحية "أشوف بياناتي أنا بس" للموظف العادي (تحتاج ربط ApplicationUser بسجل الموظف).
- تقارير إضافية: تحليل مراكز التكلفة، تقادم الأرصدة (Aging).
- ربط المساعد الذكي بـ WhatsApp Business API كقناة إضافية (نفس المنطق الخلفي، قناة دخول جديدة).
- OCR لقراءة صور الإيصالات والفواتير تلقائيًا بدل الإدخال اليدوي للمبلغ.
